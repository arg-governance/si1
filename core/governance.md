\# SI-1 Governance



\## Rule of Change



No change to SI-1 is valid unless:



1\. It is explicitly versioned

2\. It is documented

3\. It is reviewed before activation



\## Versioning



\- Protocol versions are immutable once committed

\- New versions must increment numerically



\## Separation of Concerns



\- Git tracks development history

\- Registry tracks protocol versions

\- Runtime tracks active behavior



\## Modification Principle



Changes must improve at least one:



\- reasoning quality

\- clarity

\- consistency

\- safety

\- modularity



Otherwise they are rejected.
